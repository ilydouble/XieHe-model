# 旧六点数据集专项审计报告

审计日期：2026-08-11

审计对象：

- datasets/pose_data：六点 YOLO Pose 候选数据；
- datasets/pose_det_data：由 Pose 六点转换的六类 YOLO Detection 数据。

本轮为只读审计，未修改、删除或移动原图和标签。

## 1. 审计范围限制

历史分析报告记录的完整 pose_data 应包含 1565 张图：

| split | 历史数量 | 当前磁盘数量 |
|---|---:|---:|
| train | 1252 | 1 |
| val | 157 | 1 |
| test | 156 | 231 |
| 合计 | 1565 | 233 |

当前目录不是当时的完整训练集。数据目录没有被 Git 跟踪，在 spine 工程树和 E 盘 spine_data 中也没有找到另一份完整副本。因此，本报告只代表当前磁盘上的 233 张副本，不能代表缺失的历史 1565 张全集。

## 2. Pose 标签类型混入

233 份 pose_data 标签并不都是六点标签：

| 类型 | 数量 | 结论 |
|---|---:|---|
| 真六点 Pose：单行、23 列、class=0 | 158 | 继续做六点质量检查 |
| 椎体四角 Pose：每行 17 列 | 75 | 误混入六点目录，应从六点任务隔离 |
| 无法识别 | 0 | 无 |

75 份椎体四角文件已与 datasets/pose_corner_data 逐一核对：

- 75/75 张图都能在椎体数据集找到，图像 SHA-256 一致；
- 75/75 份标签都能在椎体数据集找到，标签字节完全一致。

这是明确的数据集任务混入，不是六点标注质量问题。这 75 张不能参与六点训练或六点测试。

## 3. 158 份真六点标签检查

### 3.1 格式、坐标和可见性

- 六点坐标越界：0；
- bbox 坐标越界：0；
- 关键点缺失：0；
- 非法 visibility：0；
- 关键点总数：948，全部可见；
- visibility=2：498 点；visibility=1：450 点。

之前将全部 233 份标签都按六点格式解析时得到的“75 个越界坐标”需要撤销。那些不是真实六点越界，而是把 75 份椎体四角标签用六点规则误解析的结果。

### 3.2 83 份系统性坐标错误

158 份真六点中，有 83 份的全部 6 点位于图像左上 20% 范围内。视觉抽查证明其原图是覆盖锁骨、髂骨和骶骨的完整站立位 X 光，不是只保留左上局部的裁剪图。

83 份异常样本具有统一批次特征：

- 文件名全部为“数字__CR_TSPINE_日期_slice0000”；
- 498 个点的 visibility 全为 2；
- 图像宽度中位数约 3012 px，高度中位数约 5376 px；
- 包含当前唯一 train 样本、唯一 val 样本和 81 份 test 样本。

异常组与正常组的坐标比例不是单一常数：x 方向的关键点中位数相差约 6.8–7.8 倍，y 方向的锁骨点约相差 9.4–9.5 倍，髂骨/骶骨点约相差 6.35 倍。不能用“全部乘8”或“全部乘10”自动修复，否则会生成新的伪标注。

结论：83 份应全部从六点训练和验证中隔离；如要恢复，应基于原图重新标注。

### 3.3 剩余 75 份

排除 83 份坐标聚集后，剩余 75 份真六点标签通过了自动格式、坐标、可见性、纵向解剖顺序和 bbox 检查。它们全部在 test 目录：

| split | 结构通过的六点样本 |
|---|---:|
| train | 0 |
| val | 0 |
| test | 75 |

“自动检查通过”不等于人工点位一定正确。这 75 张可以作为人工复核候选，但在抽查左右语义和具体点位前，不应直接称为金标准。

## 4. 左右语义冲突

158 份真六点标签的画面 x 关系全部为：

- CR < CL；
- IR < IL；
- SR < SL。

新导出数据与旧数据重合的同一检查样本中，新标注的三组关系全部相反。这不能由随机误差解释，说明新旧数据在水平显示方向、解剖左右或标签顺序中至少有一项不一致。

在该规则统一之前，新旧六点数据不能直接合并，否则模型会同时学习相反的 L/R 语义。

## 5. Detection 数据检查

pose_det_data 共有 158 份标签：

- 158/158 文件格式合法；
- 每份都有 6 个类别唯一的点检测框；
- 158/158 与当前 Pose→Detection 转换逻辑精确一致；
- 83 份左上聚集错误也被原样转换进了 Detection 数据。

因此 Detection 数据不是独立标注，也不能用来证明 Pose 标注正确。清洗 Pose 时，Detection 必须从清洗后的 Pose 重新生成。

## 6. 重复与泄漏

- SHA-256 完全重复组：0；
- 跨 split 完全重复组：0；
- 256 位 dHash 强近重复：7 对；
- 7 对统一缩放后的像素相关系数为 0.999996–0.999998，可确认为同图重编码/重命名；
- 7 对全部在 test 中，每对都是“椎体四角混入版本 + 左上错误六点版本”。

它们不构成跨 split 泄漏，但再次证明当前 test 目录不是干净的六点测试集。

## 7. 水平翻转增强实际未生效

train_pose.py 配置了 fliplr=0.5，但六点数据 YAML 没有 flip_idx。当前环境的 Ultralytics 8.3.183 会在 Pose 任务缺少 flip_idx 时自动将 fliplr 和 flipud 都设为 0。

因此，训练脚本中声明的 50% 水平翻转并没有实际执行。但不应在未统一 L/R 语义前直接添加 flip_idx：需先确定水平翻转后 CR/CL、IR/IL、SR/SL 是保持解剖身份，还是按画面左右互换。

## 8. 最终判定

| 数据组 | 数量 | 当前处理建议 |
|---|---:|---|
| 椎体四角误混入 | 75 | 从六点任务隔离 |
| 六点全部聚集左上 | 83 | 隔离，原图重新标注 |
| 自动结构检查通过 | 75 | 人工抽查后作为候选，目前全在 test |
| 当前可用 train | 0 | 不可训练 |
| 当前可用 val | 0 | 不可验证 |

结论：当前 pose_data 和 pose_det_data 都不能原样用于继续训练。当务之急不是调参，而是找回历史完整数据，统一图像水平方向和 L/R 语义，隔离错误批次，再按 75 份候选样本的规则对全量数据重新审计和划分。

## 9. 复现方法

运行：

    python3 scripts/audit_legacy_six_point_dataset.py datasets/pose_data --detection-dir datasets/pose_det_data --output /private/tmp/旧六点数据集审计

脚本输出：

- audit.json：机器可读完整结果；
- issues.csv：逐样本隔离清单；
- report.md：自动摘要。
