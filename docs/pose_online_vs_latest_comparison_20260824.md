# 六点 Pose 线上基线与最新版对比

## 结论

在患者隔离后的同一套 175 张原始 test 上，最新版 `best_performance-5` 相对同规范线上基线候选 `best_performance-3` 明确变好。

按 `xiehe-system` 当前真实推理口径（原图单阶段、不裁黑边、`imgsz=640`、候选 `conf=0.25`、最终框置信度不低于 0.5、执行点集塌缩拒绝）：

| 指标 | 线上基线候选 | 最新版 | 变化 |
|---|---:|---:|---:|
| 六点召回 | 1050/1050 | 1050/1050 | 持平 |
| 点加权平均误差 | 39.739 px | 33.742 px | 改善 5.997 px（15.1%） |
| 中位误差 | 30.324 px | 26.139 px | 改善 4.185 px |
| P90 误差 | 85.775 px | 69.896 px | 改善 15.879 px |
| PCK@20 px | 30.67% | 38.29% | 提升 7.62 个百分点 |
| CPU 单图推理均值 | 97.704 ms | 93.786 ms | 无速度代价 |

逐图有 124 张改善、51 张恶化；逐图改善中位数为 4.227 px。以逐图差值做 20,000 次确定性配对 bootstrap，平均改善的 95% 区间为 4.279–7.828 px，区间未跨 0。结论不是由少数极端样本单独拉动。

## 系统性纵向偏差

正数 `dy` 表示预测低于标注，负数表示预测高于标注。

| 指标 | 线上基线候选 | 最新版 |
|---|---:|---:|
| 两肩点平均 dy | -7.863 px | +0.457 px |
| 两肩点均值高于标注的图像 | 73.14% | 45.71% |
| 下四点平均 dy | +5.490 px | +3.135 px |
| 下四点均值低于标注的图像 | 61.71% | 61.14% |
| 纵向跨度偏差 | +13.353 px | +2.678 px |
| 纵向跨度相对偏差 | +0.68% | +0.18% |

最新版基本消除了“肩点普遍偏高”和整体上下跨度扩大的问题；下四点仍有小幅向下偏差，方向出现比例没有明显下降，但平均幅度降低。

## 输入尺寸敏感性

此前同一 175 张 test、同为原图单阶段的 `imgsz=800` 结果也已核对模型哈希：

| 指标 | `best_performance-3` | `best_performance-5` |
|---|---:|---:|
| 平均误差 | 41.403 px | 29.850 px |
| 中位误差 | 30.785 px | 21.639 px |
| P90 误差 | 87.628 px | 64.947 px |
| PCK@20 px | 29.81% | 46.38% |

最新版是在 `imgsz=800` 上训练的；它从线上 640 提到 800 后，平均误差进一步由 33.742 降到 29.850 px。但本机 CPU 首轮推理均值约由 93.8 ms 增至 138.4 ms，不能直接把 800 写入线上而不测真实 GPU 延迟和并发。

## 权重与线上边界

- 线上基线候选：`best_performance-3/weights/best.pt`，SHA-256 `26414c7d6c2674136e00250f073e179e1976ddf5815f7a24b53069ebb3ef0707`。
- 最新版：`best_performance-5/weights/best.pt`，SHA-256 `cf4af724d5707bf888f826225bcc5924f2986b8b44ab1d69c201de001a9740e7`。
- `xiehe-system` 当前工作副本忽略且不包含 `model/ap/weights/pose.pt`，公网 8001 地址也无法连接，因此本地无法对服务器正在运行的权重做 SHA-256 证明。
- 仓库 `3-inference/weights/pose.pt` 的 SHA-256 为 `e4b945da6f7283f1f66454474e77d93a02d5830e75f3648ccd8db745869b30cc`，与 2026-05-11 的旧语义 `best_performance2` 相同，不能在当前 normalized 线上代码中直接当作部署基线。

上线替换前应在服务器执行 `sha256sum model/ap/weights/pose.pt`。如果结果是 `26414c7d...f0707`，本报告就是严格的旧线上权重对最新版比较；若哈希不同，需要把服务器权重拷回或直接在服务器按同一脚本补跑，不能把本报告错误命名为已核验的实际线上权重。

## 建议

1. 可以把 `best_performance-5` 作为新的单阶段候选，先不要启用此前已证实会恶化的同权重二阶段。
2. 先以线上现有 `imgsz=640` 替换权重做灰度验证；再单独 A/B `imgsz=800`，用线上 GPU 的 P50/P90 延迟和并发决定是否提高输入尺寸。
3. 不新增黑边裁剪。当前对比已按线上原图链路完成，裁剪会引入另一项变量。
4. 上线门槛除总体均值外，继续检查 51 张恶化样本，尤其旧来源中的 29 张；保留肩点 dy、下四点 dy 和跨度偏差监控。
