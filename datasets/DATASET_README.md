# 脊柱 AP 正位训练数据集说明

更新日期：2026-08-25

本文档描述 `datasets/` 下当前实际参与训练的两套活动数据：六点姿态数据集 `pose_data` 和椎体四角点数据集 `pose_corner_data`。数据数量与质量统计基于 2026-08-12 患者级重分后的活动文件重新计算；Corner类别统计包含2026-08-24恢复的V18/L6与V19/T13，模型状态和独立test结论更新至2026-08-25，不沿用旧报告中的历史数量或旧权重结论。

## 1. 当前数据概览

| 数据集 | 任务 | 总数 | train | val | test | 训练/验证/测试比例 | 磁盘占用 |
|---|---|---:|---:|---:|---:|---:|---:|

两套数据彼此是独立训练任务，但当前有 1,668 个同名图像文件同时用于两个任务：其中 995 个为 `eap_` 人工数据，673 个为旧数据或服务器数据。同一病例服务于两个不同模型不属于单个数据集内部重复；评估时仍应分别看各任务自己的 split。

## 2. `pose_data`：整体脊柱六点数据

### 2.1 任务和标签规范

每张图只有 1 个 `spine` 实例，每份标签恰好 1 行、23 个字段：

```text
cls cx cy w h x_CR y_CR v_CR x_CL y_CL v_CL x_IR y_IR v_IR
                  x_IL y_IL v_IL x_SR y_SR v_SR x_SL y_SL v_SL
```

所有坐标和 bbox 均为相对于图像宽高归一化后的 `[0,1]` 数值。关键点固定顺序为：

| 索引 | 缩写 | 解剖含义 |
|---:|---|---|
| 0 | CR | 右侧锁骨最高点 |
| 1 | CL | 左侧锁骨最高点 |
| 2 | IR | 右侧髂骨最高点 |
| 3 | IL | 左侧髂骨最高点 |
| 4 | SR | 骶一上终板右缘点 |
| 5 | SL | 骶一上终板左缘点 |

当前统一的图像坐标语义是：画面左侧为 `CL/IL/SL`，画面右侧为 `CR/IR/SR`，即全部 1,755 份均满足 `x_CL < x_CR`、`x_IL < x_IR`、`x_SL < x_SR`。训练配置中的水平翻转映射为：

```yaml
flip_idx: [1, 0, 3, 2, 5, 4]
```

因此训练时若做水平翻转，会同步交换 `CR↔CL`、`IR↔IL`、`SR↔SL`，不会改变左右解剖身份。

### 2.2 构建过程

当前 1,755 份六点数据由 685 份清洗后的历史数据和 1,070 份经过正式分配或人工重复核对的数据组成。

1. 历史目录最初含 2,308 份候选，其中混入了 743 份椎体四角点任务标签；另有 879 份六点坐标被系统性压缩在左上角。这两批均未进入当前六点活动集。
2. 清理后剩余 686 份六点数据。人工修正其中 3 份关键点槽位异常，并隔离 1 张无法完整解码且不能安全恢复的 PNG，形成 685 份历史基础集。
3. 这 685 份历史标签曾使用相反的左右槽位约定，现已统一交换三组左右标签，图像像素本身没有水平翻转。
4. 从 E 盘新数据中只使用 `assignment_all.xlsx` 覆盖的正式人工标注，首次净导入 809 份。非正式测试数据、混合左右样本和目标数据中已有的精确重复未纳入。
5. 再依据 284 组人工重复核对结果导入 263 份，并移出 2 份被人工否决的既有代表，最终得到 `685 + 809 + 263 - 2 = 1,755` 份。
6. 最后按可识别患者整组重分为 1,404/176/175；共移动 52 对图像与标签，使同一可识别患者不跨 train、val、test。

按文件来源前缀统计：

| 来源 | train | val | test | 合计 | 占比 |
|---|---:|---:|---:|---:|---:|
| 历史清洗数据（非 `eap_`） | 526 | 82 | 77 | 685 | 39.03% |
| 正式人工/人工核对数据（`eap_`） | 878 | 94 | 98 | 1,070 | 60.97% |
| 合计 | 1,404 | 176 | 175 | 1,755 | 100% |

### 2.3 数据和标注分布

- 图像模式：灰度 984 张、RGB 727 张、RGBA 44 张。
- 图像宽度：191–3,121 px，中位数 1,720 px。
- 图像高度：425–6,698 px，中位数 3,704 px。
- 共 1,172 种图像尺寸，说明数据来自多种设备、导出和预处理链路。
- 实例数：1,755；每图恒为 1 个实例。
- 关键点总数：10,530；没有 `v=0` 的缺失点。
- `v=1`：4,110 个，占 39.03%，全部来自历史 685 份。
- `v=2`：6,420 个，占 60.97%，全部来自 `eap_` 1,070 份。

YOLO Pose 通常把可见性 `v=0/1/2` 解释为“未标注或不存在/已标注但不可见/已标注且可见”。当前 Ultralytics 训练实现对 `v!=0` 的点都会计算有效关键点损失，因此 `v=1` 和 `v=2` 都会参与训练。这里的 1/2 分布主要反映两批标注元数据约定不同，而不是 39.03% 的关键点坐标缺失；如果以后换用严格区分遮挡状态的框架，应先统一该字段。

## 3. `pose_corner_data`：椎体四角点数据

### 3.1 任务和标签规范

一张图通常有 18 行，每行表示一节椎体，格式为 17 个字段：

```text
cls cx cy w h x_TL y_TL v_TL x_TR y_TR v_TR
                 x_BR y_BR v_BR x_BL y_BL v_BL
```

四角顺序固定为 `TL/TR/BR/BL`，水平翻转使用 `flip_idx: [1,0,3,2]`，即 `TL↔TR`、`BL↔BR`。

| 类别 | 椎体 | 类别 | 椎体 |
|---|---|---|---|
| V0 | C7 | V9 | T9 |
| V1 | T1 | V10 | T10 |
| V2 | T2 | V11 | T11 |
| V3 | T3 | V12 | T12 |
| V4 | T4 | V13 | L1 |
| V5 | T5 | V14 | L2 |
| V6 | T6 | V15 | L3 |
| V7 | T7 | V16 | L4 |
| V8 | T8 | V17 | L5 |
| V18 | L6 | V19 | T13 |

V0 对应 C7，不是额外的未知椎体；V1–V12 对应 T1–T12，V13–V17 对应 L1–L5。V18/L6和V19/T13是少数病例才存在的可选类别，普通病例缺少它们是合法状态。类别ID按历史数据定义保留，因此V19/T13的解剖位置实际在V12/T12和V13/L1之间，不能把所有预测按y坐标排序后直接编号为V0–V19。

### 3.2 构建过程

当前 2,499 份角点数据由服务器去重版 1,381 份和正式人工数据 1,118 份组成。

1. 历史 743 份角点数据经重叠样本和未重叠样本抽查后，被确认椎体编号和角点整体不够准确，因此没有继续参与当前活动训练集。
2. 从服务器数据中先处理内部同图重复，保留 1,381 份。服务器标签中的 class 18/L6 共44行、class 19/T13共11行最初按18类契约过滤；2026-08-24决定扩展为20类并从原始标签增量恢复，病例图像与其余标签始终保留。
3. 保留 E 盘 `assignment_all.xlsx` 范围内的 871 份正式人工角点标注；4 份非正式测试数据没有进入活动集。
4. 根据 284 组人工重复核对结果再增加 247 份，并用人工确认版本替换 G0247 的既有标签，形成 `1,381 + 871 + 247 = 2,499` 份。
5. 最后按可识别患者整组重分为 1,999/250/250；共移动 231 对图像与标签，修复原服务器 split 中 39 名可识别患者跨分区的问题。

按来源统计：

| 来源 | train | val | test | 合计 | 占比 |
|---|---:|---:|---:|---:|---:|
| 服务器去重数据（非 `eap_`） | 1,044 | 156 | 181 | 1,381 | 55.26% |
| 正式人工/人工核对数据（`eap_`） | 955 | 94 | 69 | 1,118 | 44.74% |
| 合计 | 1,999 | 250 | 250 | 2,499 | 100% |

### 3.3 数据、实例和类别分布

- 图像模式：灰度 1,682 张、RGB 758 张、RGBA 59 张。
- 图像宽度：191–3,208 px，中位数 2,736 px。
- 图像高度：425–7,338 px，中位数 4,692 px。
- 共 1,883 种图像尺寸。
- 椎体实例总数：45,036；角点总数：180,144。
- 按每图实例数：2,446张为18个实例、52张为19个实例、1张为20个实例。
- 基础类别V0–V11、V13–V17每类均有2,499个实例；V12有2,498个实例。可选类别V18/L6有44个实例，V19/T13有11个实例。
- 全部180,144个角点的visibility均为`2`。

唯一已知的不完整样本为：

```text
train/3557232367__CR_TSPINE_20210927_slice0000.png
```

其标签缺少class 12，即V12/T12，但历史标签含一个额外椎体，因此恢复后总实例数仍为18。该样本当前保留；校验基础结构时必须按类别集合判断，不能只按实例数量判断。

### 3.4 bbox 统一规则

2026-08-12 已将全部角点标签的 bbox 统一为 `TL/TR/BR/BL` 四点的水平最小外接框，不添加边距。YOLO Pose 的 `cx cy w h` 是轴对齐框，本身不表达椎体旋转；椎体方向由四个关键点表达。

统一前，人工 `eap_` 数据的 20,124 个椎体框已经符合该规则；服务器 24,857 个实例中有 21,253 个实例的框与四点范围不一致。正式处理仅修改 1,381 份服务器标签中这 21,253 行的 `cx cy w h`：

- class、`TL/TR/BR/BL`、visibility 和行序完全不变；
- 1,118 份人工标签保持原字节不变；
- 图像与 train/val/test 划分均未修改；
- 统一后 44,981/44,981 个实例均符合四点水平外接框规则。

修改前全部 2,499 份标签备份在 `../datasets/pose_corner_bbox_backup_20260812/`，其中 `manifest.json` 保存逐文件修改前后 SHA-256，可用于复核或回退。可复现工具为 `../scripts/normalize_corner_bboxes.py`。

## 5. 质量边界和剩余风险

1. **患者标识并非全量可得。** 两套数据各有 412 份只能够从文件名解析出 DICOM 检查 UID，无法取得可靠患者号。重分时这些样本固定在原 split。因而“患者级泄露为 0”只针对能够解析 `assignment` 患者号、业务患者号或服务器数字患者号的样本；412 份未知患者样本之间是否存在隐含关联，当前无法证明或排除。
2. **精确去重不等于所有近重复都被排除。** 当前 SHA-256 完全相同图像为 0，人工核对的 284 组重复也已处理，但不同分辨率、不同窗宽窗位或不同裁剪的同源图像仍可能逃过精确哈希检查。
3. **六点 visibility 有历史约定差异。** `v=1` 和 `v=2` 当前都会参与 Ultralytics 训练，但迁移到其他框架前应确认其掩码规则。
4. **角点 bbox 已统一，但仍是水平框。** 当前所有框均由四点计算且定义一致；椎体旋转只由四角点表达。该设计符合标准 YOLO Pose 标签格式，不等同于旋转目标检测框。
5. **自动规则不能替代逐例医学审核。** 当前“质量通过”表示格式、坐标、解码、顺序、重复和可识别患者隔离通过，并不等于每个点均达到专家级像素精度。服务器角点版曾做分层人工抽样并被认为基本正确，人工 `assignment` 数据有更直接的人工来源，但仍建议在模型出现局部异常时回查原图和标签。

综合判断：两套数据当前均可用于正式训练；六点集的结构和左右规范较统一，最主要的元数据差异是 visibility；角点集的四角点和 bbox 规范已经统一，当前主要已知标签例外是单张缺 V12。

## 6. 划分策略和后续增量原则

当前 split 采用约 80%/10%/10%，并以“同一可识别患者不能跨 split”为优先约束。未来继续导入数据时应遵循：

1. 先核对是否属于正式人工分配范围，不把测试标注或临时实验输出直接导入。
2. 先做图像内容去重，再决定保留哪一版标签；不能只按文件名判断重复。
3. 同一患者的所有日期和检查必须整体分配到单一 split。
4. 已进入 val/test 的患者新增图像应继续留在该患者原有 split，不应重新加入 train。
5. 六点必须保持 `CR/CL/IR/IL/SR/SL` 槽位和当前左右语义；角点必须保持 `TL/TR/BR/BL`。
6. 每次增量后重新执行图像解码、配对、标签结构、坐标、左右/几何、精确重复和患者级交叉检查，并记录迁移清单。

### 7.1 当前已训练模型与独立test结论

| 任务 | 当前候选权重 | 实际训练配置 | 相对上一版的独立test结论 |
|---|---|---|---|
| 六点Pose | `6-train_ap_model/runs/pose/best_performance-5/weights/best.pt` | YOLO11l-pose，原图+ROI，200轮，batch4，imgsz800，低增强 | 175张线上640单阶段：平均误差39.739→33.742 px，改善15.1%；选择最新版单阶段 |
| Pose Corner | `6-train_ap_model/runs/corner/corner_20class_roi_mixed_v1-2/weights/best.pt` | YOLO11l-pose，原图+ROI，20类，150轮，实际batch4，imgsz800，低增强 | 修正标签后的250张只评V0–V17：14.945→14.135 px，改善5.42%；完整图231→239 |

Corner当前主业务评价仍是V0–V17。V18/L6与V19/T13用于避免真实额外椎体继续作为未标注背景，并作为辅助监督保留；它们的test仅各3例，召回不作为当前Corner权重的淘汰标准。最新Corner在V0–V17上属于总体小幅提升，但不同来源并不一致，完整边界见`../docs/pose_and_pose_corner_latest_comprehensive_report_20260825.md`。

二阶段低成本精修实验使用已有`pose_roi_views`的1404张train ROI，从一阶段`best_performance-5/best.pt`初始化独立权重，以30轮、AdamW `lr0=0.0003`全模型微调。该实验已经在175张独立test上完成：一阶段平均误差29.850 px，二阶段best为38.800 px，且推理耗时近乎翻倍。因此当前不采用二阶段，相关YAML和脚本只保留用于复现或后续预测ROI对照实验。详细结果见`../docs/pose_stage2_best_evaluation_20260824.md`。

`pose_data_roi_mixed.yaml`的train同时引用原始1404张train和`pose_roi_views`的1404张派生ROI视图，因此训练样本数为2808；val/test仍只引用原始176/175张，患者分区没有改变。ROI视图由原bbox与六点并集扩展20%上下文，并加入确定性的5%平移和10%尺度扰动后生成；原始`pose_data`没有被覆盖。推荐命令：

```bash
cd 6-train_ap_model
./train_pose.sh --best --roi-mixed --device 0 --name best_performance_roi_mixed
```

该快捷入口同时选择`roi_low`低增强预设，避免mosaic、mixup、copy-paste、强scale等增强干扰ROI实验归因。该数据用于训练同一个模型兼容原图第一次定位与ROI第二次精定位；最终效果必须在原始test图上通过完整线上流程评估，不能直接用GT裁剪后的test替代。

`corner_data_roi_mixed.yaml`的train同时引用原始1999张Corner train和`corner_roi_views`的1999张派生ROI视图，因此训练样本数为3998；val/test保持原始250/250。派生层中1212张安全图像以硬链接复用现有`pose_roi_views`像素，40张因原Pose框会切到Corner角点而扩框重裁，747张无现成Pose ROI而按真实ROI几何分布生成；真正新增像素文件787张，约占3.261GiB。全部ROI强制包含每图所有椎体bbox和可见角点。生成或增量更新命令：
